# ADR-0007: Saga — coreografiada vs orquestada

- **Status:** Accepted
- **Date:** 2026-07-09
- **Deciders:** Project owner

## Context

A "suscripción creada" flow spans multiple services:

1. `payment-service` creates a subscription record.
2. `user-service` upgrades the user's role.
3. `notification-service` sends a welcome email.

There's no global transaction across services (per ADR-0003). We need a
way to keep these consistent.

## Options

- **Two-phase commit (XA)**: rejected — doesn't scale and ties us to a
  specific DB.
- **Choreographed Saga**: each service emits events, others listen and
  react. No central coordinator.
- **Orchestrated Saga**: a central orchestrator (Temporal, Camunda, or
  a custom step machine) drives the flow.

## Decision

We use **both**:

- **Choreographed** as the **default**. Implemented with Kafka topics
  and `@KafkaListener`s. Simpler to start.
- **Orchestrated** for flows with **non-trivial compensation** (e.g.,
  payment + billing + entitlement that can fail at different points and
  need retries with timeouts). We evaluate Temporal vs. a lightweight
  in-house orchestrator in Fase 7+.

## Rationale

- Choreographed Sagas work well when steps are simple and the
  compensation is local ("if I can't upgrade the user role, don't bill
  them"). They fail when the steps are complex.
- Orchestrated Sagas are easier to **observe** (one place to look for
  "where is flow X?"). They are heavier to operate.
- Mixing them lets us start with choreographed and graduate only the
  flows that need it.

## Consequences

- All events that participate in a saga are **versioned** in the
  `event-contracts` module.
- Compensations are **explicit code paths**, not "undo operations" on
  JPA entities. We don't try to roll back the world.
- We need a **correlation id** on every event so we can trace a saga
  instance.
- Saga state is **not** stored in any one place; it lives in the events
  emitted so far. We accept that to debug a saga you have to read
  Kafka.

## Trade-offs accepted

- Eventual consistency: a saga may take seconds to fully complete.
- A failed compensation may require manual intervention. We add
  monitoring and runbooks.
