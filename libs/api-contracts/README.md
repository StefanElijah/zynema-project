# @zynema/api-contracts

TypeScript type definitions shared between the **BFF** (which is also a
TypeScript/Node project conceptually — or in our case, the generated client
the frontend uses) and the **frontend**. The Java backend doesn't consume
these directly; it generates them from its own springdoc-openapi specs.

## Status

- **Empty in Fase 0.** The first contracts are defined in **Fase 2**
  (catalog) and grow from there.
- Will be auto-generated by `openapi-typescript-codegen` in CI from the
  BFF's OpenAPI spec (Fase 8).

## Conventions

- All types **mirror** the Java DTOs in `backend/common/.../dto/`.
- We use **camelCase** in TS and **camelCase** in Java (no
  snake_case mapping).
- `null` vs `undefined`: TS uses `undefined` for "absent"; Java
  `@Nullable` maps to `T | null` in the generated client. We pick
  `T | null` for nullable fields in shared types.
- Dates are ISO 8601 strings in transit (`string`), not `Date`.
